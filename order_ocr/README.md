# 訂單 OCR 準確度優化流程（原型）

把掃描或傳真的採購單轉成 ERP 可匯入的訂單資料。重點不只是「讀得出來」，而是**用流程設計把讀錯的資料攔下來**：能確定正確的自動放行，有疑慮的才交給人工。

**零成本**：使用 Windows 內建的繁體中文 OCR，離線執行，不需要任何 API 費用。

> 所有樣本的公司、料號、金額都是虛構資料。

## 成果

| 階段 | 開發樣本（20 張） | 測試樣本（40 張，規則沒看過） |
|---|---|---|
| ① 原始 OCR | 70.3% | 68.6% |
| ② ＋影像前處理 | 77.9% | 76.2% |
| ③ ＋主檔比對與交叉驗證 | **96.3%** | **92.1%** |
| 自動放行 | 14 張，全部正確 | 26 張，全部正確 |
| 送人工確認 | 6 張 | 14 張 |

（欄位準確率 = 客戶、單號、日期、合計及每個品項的料號／數量／單價／金額，逐欄比對正確答案。）

**錯誤單據被自動放行：0 張。** 對 ERP 來說，這比整體準確率更重要，因為錯誤資料一旦進系統，後續的排程、出貨、請款都會跟著錯。

## 流程

```
採購單影像（掃描／傳真）
   │
   ▼
① OCR ───────── Windows 內建 OCR 辨識文字與位置，依版面欄位位置分配到各欄
   │
   ▼
② 影像前處理 ─── 取紅色通道去除紅色印章；以文字座標估算傾斜並校正
   │
   ▼
③ 規則驗證 ───── 客戶、料號是否在主檔；單號格式；日期合理性；
   │              數量 × 單價 = 金額；明細加總 = 合計
   ▼
④ 自動修正 ───── 只修「有唯一答案、且有其他欄位佐證」的錯誤：
   │              ・0/O、1/I、5/S、8/B 等易混淆字元 → 比對主檔
   │              ・料號模糊比對 → 需單價符合該料號標準價才採用
   │              ・單價小數點遺失 → 由金額 ÷ 數量回推，並比對標準價
   │              ・數量 × 單價 ≠ 金額 → 推算哪一欄讀錯，以單據合計交叉驗證
   │              ・客戶名稱相似但不一致 → 不自動改寫，列出最接近的主檔名稱送人工
   ▼
⑤ 分流 ───────── 全部通過 → 自動放行，寫入 ERP 匯入檔
                  仍有錯誤 → 人工確認清單
```

## 檔案

| 檔案 | 用途 |
|---|---|
| `generate_samples.py` | 產生模擬採購單（乾淨、蓋章、雜訊、低解析傳真四種難度）和正確答案 |
| `local_ocr.py` | 零成本 OCR：影像前處理、Windows OCR、版面解析 |
| `ocr_pipeline.py` | 主流程：驗證、自動修正、分流、輸出 Excel（也可切換成 Claude API） |
| `evaluate.py` | 逐階段評估準確率 |
| `dashboard.py` | 視覺化儀表板 |
| `output/erp_import.xlsx` | 訂單抬頭、訂單明細、人工確認清單、自動修正紀錄 |

## 執行

```bash
py -m pip install winocr pillow openpyxl streamlit plotly pandas
py generate_samples.py
py generate_samples.py --n 40 --seed 2026 --out samples_test
py evaluate.py
py evaluate.py --folder samples_test
py ocr_pipeline.py samples
streamlit run dashboard.py
```

儀表板有三頁：
- **成果總覽**：各階段準確率、不同掃描品質的表現、分流結果、自動修正類型統計。
- **單張檢視**：原圖與 OCR 文字框；逐欄比對每個階段的結果，並列出修正紀錄與送人工確認的原因。
- **上傳試試**：上傳一張採購單，即時跑完整流程。

## 限制與後續

- 樣本是模擬資料，真實掃描檔的版面、字體、劣化方式會更多樣，需要用真實單據重新評估。
- 版面解析依賴固定的欄位位置（範本式 OCR），每種客戶表單需要設定一組範本。
- 若預算允許，可切換為 AI 視覺模型（`--engine claude`），處理版面不固定的單據；驗證與分流規則可以沿用。

## 與公司系統串接（理論設計）

| 方式 | 說明 | 適用情境 |
|---|---|---|
| 檔案匯入 | 依 ERP 的匯入範本產生 CSV／Excel，由系統排程或人員匯入 | 最容易導入，不需改動 ERP |
| API 串接 | 驗證通過的訂單直接呼叫 ERP 建單 API；SAP 可用 BAPI（如 `BAPI_SALESORDER_CREATEFROMDAT2`）或 IDoc（`ORDERS05`） | 量大、需要即時建單 |
| RPA | 機器人模擬人工在 ERP 畫面輸入 | 系統沒有開放 API |

不論哪種方式，建議保留：
1. **人工確認關卡**：有疑慮的單據不自動建單。
2. **主檔同步**：客戶與料號主檔定期從 ERP 匯出，確保驗證規則使用最新資料。
3. **紀錄可追溯**：保留原始影像、辨識結果、修正紀錄與人工修改，作為稽核依據，也用來持續改善規則。
