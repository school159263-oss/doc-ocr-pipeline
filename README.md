# 單據自動判讀：作品集

林彥廷・個人專案・2026.10
全本機執行，不使用付費 API。**所有測試單據都是自行產生的虛構資料。**

## 一句話說明

把掃描、傳真的單據自動轉成系統資料。目標不是讓機器零錯誤，而是**讓錯誤不會悄悄進入 ERP**：
確定正確的自動通過，沒把握的一定交給人確認。主要指標是「自動通過單據的正確率」。

## 怎麼看（不用寫程式）

| 想看什麼 | 怎麼做 |
|---|---|
| 發票／進料單／出貨單的判讀結果 | 雙擊 **`開啟_發票單據儀表板.bat`** |
| 採購單品項明細的判讀結果 | 雙擊 **`開啟_採購單儀表板.bat`** |

儀表板第一次開啟會自動安裝 Python 套件，約需幾分鐘，之後幾秒就能開好，瀏覽器會自動跳出。
看完關掉那個黑色視窗就會停止。
發票儀表板需要先產生測試單據（檔案較大，未放進 repo）：在 `doc_pipeline/` 執行 `python generate_docs.py` 與 `python generate_docs.py --holdout`。需要電腦已安裝 Python；發票儀表板標示欄位位置時會用到 Tesseract OCR。

## 專案一：發票、進料單、出貨單（`doc_pipeline/`）

Tesseract OCR（原生 PDF 直接讀文字層）→ 規則抽取單號、日期、廠商、總額 → 共用查檢 → 自動通過或送人工複核。

| 階段 | 自動通過 | 自動通過者正確 | 錯誤漏網 |
|---|---|---|---|
| 基準線（第一版規則） | 15/20 | 8/15（53.3%） | 7 份 |
| 規則調整＋小計加稅額交叉檢查 | 16/20 | 15/16（93.8%） | 1 份 |
| 保留測試集（規則未再調整） | 12/20 | 11/12（91.7%） | 1 份 |
| ＋廠商主資料比對（原測試集） | 15/20 | 15/15（100%） | 0 份 |
| ＋廠商主資料比對（保留測試集） | 11/20 | 11/11（100%） | 0 份 |

儀表板三頁：**掃描文件**（每份文件的縮圖與判讀結果）→ **單份檢視**（在原圖上標出各欄位的讀取位置）→ **統計數據**。

## 專案二：採購單品項明細（`order_ocr/`）

Windows 內建 OCR → 去除紅色印章 → 依版面位置解析每一列品項 → 主檔比對、數量 × 單價 × 合計交叉驗證 → 自動放行或人工確認 → 輸出 ERP 匯入用 Excel。

| 階段（欄位準確率） | 開發樣本 20 張 | 測試樣本 40 張（規則未看過） |
|---|---|---|
| ① 原始 OCR | 70.3% | 68.6% |
| ② ＋影像前處理（去除紅色印章） | 77.9% | 76.2% |
| ③ ＋主檔比對與交叉驗證 | 96.3% | 92.1% |
| 自動放行（其餘送人工確認） | 14 張，全部正確 | 26 張，全部正確 |

ERP 匯入檔範例：`order_ocr/output/erp_import.xlsx`（訂單抬頭、訂單明細、人工確認清單、自動修正紀錄）。

## 設計原則

1. **主指標是自動通過者的正確率**：被攔下來送人工的錯誤不會造成損害；自動通過的錯誤會直接進系統。
2. **規則與驗證分開**：規則在一批文件上調整，再用另一批沒看過的文件驗證。
3. **只修正有佐證的錯誤**：例如由「金額 ÷ 數量」回推單價並比對標準價；名稱相似但不一致時不自動改寫，送人工確認。
4. **樣本小就標出份數**：每個比例都附上分子分母，例如 11/12。

## 限制

- 測試單據為虛構資料，每批 20～40 份；這是方法示範，不是上線準確率保證。
- 主資料比對屬於封閉世界測試（測試文件的廠商都在主資料內）。
- 下一步：以去識別化的真實單據重新驗證、比較不同 OCR 引擎，並依公司 ERP 匯入範本對接。
